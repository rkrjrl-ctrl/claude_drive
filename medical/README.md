# 의료 근거자료 저장소 (영상 제작용)

신장암 및 7대 암(갑상선·위·대장·폐·유방·간·전립선)과 췌장암·담낭암·담도암을 중심으로, 뇌혈관·심장·대사·호흡기 등 주요 질환까지 영상 제작에 쓰는 의료·치료비·제도 근거자료를 **파일 1개 = 자료 1건**으로 보관한다.
정본은 이 저장소이며, 이후 수집·검증은 Claude Code가 이어서 진행한다.
(이전 방식: Drive 시트 `휴휴휴 의료정보_자료목록과 운영흐름` + 건별 txt. 이전 내역은 [MIGRATION.md](MIGRATION.md))

## 구조

| 위치 | 내용 | 수정 방법 |
|---|---|---|
| `sources/MED-NNNN_<기관>_<주제>.md` | 자료 1건 (머리말 + 본문 4섹션) | 사람/Claude가 작성 |
| `index.csv` | 전 자료 목록 (엑셀로 열기 가능) | **자동 생성** — 직접 수정 금지 |
| `STATUS.md` | 건수·보완 필요 자료·재확인 기한 | **자동 생성** — 직접 수정 금지 |
| `BY_DISEASE.md` | 질병·주제별 자료 목록 | **자동 생성** — 직접 수정 금지 |
| `BACKLOG.md` | 다음 수집·보완 작업 | 작업 후 갱신 |
| `scripts/build_index.py` | 검증 + 인덱스 생성 | |

자료를 추가·수정한 뒤에는 항상 `python3 medical/scripts/build_index.py --strict` 를 실행한다. 오류가 0이어야 커밋한다.

## 자료 파일 형식

머리말(`---` 사이)은 `키: 값` 한 줄씩, 그 뒤에 아래 4개 섹션을 **모두** 둔다.

```
## 핵심 근거          원문이 말하는 것 (요약·재서술, 직접 인용 최소화)
## 적용 조건·한계     누구에게/언제까지 적용되는지, 오해하기 쉬운 지점
## 미검증·사용 금지   확인 못 한 것, 영상에 쓰면 안 되는 표현·수치
## 영상 활용 메모     어떤 장면에 어떤 수위로 쓸지
```

| 키 | 설명 |
|---|---|
| `id` | `MED-0001` 형식. 결번 없이 순차(다음 번호 = 최대값+1). 파일명은 `<id>_`로 시작 |
| `title`, `org` | 자료명, 발행기관 |
| `jurisdiction` | `KR` / `US` / `INT` |
| `category`, `disease` | 분류(진료지침·해부학·진단/개요·치료·치료·생활관리·검진·치료비·국가제도·역학·통계·합의문·입장문·암 지지요법·유전·보험분쟁·민원), 원문 표기 질병명 |
| `group`, `topic` | 대분류(15개, `build_index.py`의 목록만 허용)와 정리된 질병명. `BY_DISEASE.md`가 이 둘로 묶인다. 새 자료는 같은 질병의 기존 자료와 같은 `topic`을 쓴다 |
| `url` | 원문 주소 (동일 원문 중복 판별에 사용) |
| `published` · `revised` · `effective` · `checked` | **발행일 · 수정일 · 시행일 · 확인일**. 서로 섞지 않는다 |
| `location` | 원문 위치(절·표·쪽·공고번호) |
| `source_type` | `web_summary` / `pdf_original` / `law` / `notice` / `guideline_summary` |
| `tier` | 근거 등급 (아래) |
| `status` | 상태 (아래) |
| `recheck_by` | 다음 재확인 기한(날짜) |
| `reviewer` | 누가 정리·검토했나. 의료인 검토를 받으면 이름·일자 기재 |
| `drive_file` | Drive에 보관된 원본/기존 파일 링크. 없으면 `없음(저장소 보관)` |
| `video_use` | 사용된 영상·장면 (미사용이면 `미배정`) |
| 선택: `related`, `supersedes`, `superseded_by`, `note`, `migrated_from` | |

### 날짜 규칙
- 값은 `YYYY-MM-DD`, `YYYY-MM`, `YYYY` 또는 `unknown` 만 쓴다. "미확인/미표기/본문 미표기" 같은 말은 쓰지 않는다 (검증기가 오류 처리).
- 원문 본문에 표시된 날짜만 쓴다. URL 속 숫자(예: `20260608`)나 첨부파일명 날짜를 발행일·수정일로 옮기지 않는다. 페이지 메타데이터에서 가져온 날짜는 `note`에 출처를 밝힌다.
- 공고·법령의 시행일은 `effective`에 쓰고 `revised`에 넣지 않는다.
- `checked`(내가 원문을 연 날)는 필수. 연 적이 없으면 자료를 만들지 않는다.

### 근거 등급 `tier`
- **A** 법령·고시·공고·대법원 판례·학회 진료지침 — 숫자·조건·급여 판단의 근거로 쓸 수 있다.
- **B** 국내 공공기관 환자·제도 안내 — 개요·절차 설명에 쓴다. 숫자(%·금액·기준)를 영상에 쓰려면 A 자료로 교차 확인한다.
- **C** 해외 자료·보조 자료·오래된 일반 안내 — 개념 설명 보조용. **국내 제도·급여·법 설명의 근거로 쓰지 않는다.**

### 상태 `status`
- `verified` 원문과 대조 완료(적용 범위 한정). 개인 적용·최신성은 별개.
- `partial` 핵심 원문(첨부 전문 등)을 확보하지 못함. 무엇이 빠졌는지 본문에 "미확보"로 적는다.
- `needs_recheck` 근거가 오래됐거나 2차 출처 등으로 교체·재확인이 필요함.
- `superseded` 개정본으로 대체됨(`superseded_by` 기재, 이력 보존) / `rejected` 쓰지 않기로 함(사유 기재).

### 재확인 기한 `recheck_by`
급여·비용·제도: 확인일+3개월 / 의학 일반: +6개월 / `needs_recheck`·`partial`: +1~2개월.
기한이 지나면 검증기가 경고하고 `STATUS.md`에 표시한다. 재확인하면 `checked`·`recheck_by`를 갱신한다.

## 수집 절차 (1건씩, 끝낸 뒤 다음으로)

1. **중복 확인** — `index.csv`에서 URL·기관·제목 검색. 이미 있으면 새로 만들지 않고 기존 자료를 갱신한다. 개정본이면 새 번호로 만들고 `supersedes` / `superseded_by`로 연결한다.
2. **수집** — 공식 출처 우선. 의학: 국가암정보센터·학회·식약처 / 비용·급여: 공단·심평원·보건복지부·법령 / 보험: 실제 약관. 웹 원문은 직접 열어 본문을 읽는다(검색 결과 요약문만으로 작성 금지).
3. **작성** — 원문을 복제하지 않고 한국어로 요약한다. 원문 이미지·도표는 가져오지 않는다.
4. **검증** — 수치·단위·대상·시행일을 원문과 한 번 더 대조한다. 확인하지 못한 것은 `미검증` 섹션에 적는다. 추정으로 채우지 않는다.
5. **실행** — `python3 medical/scripts/build_index.py --strict` → 오류 0 확인.
6. **커밋** — 자료 추가는 `medical: MED-00NN <제목>` 형식 메시지.
7. **막히면 멈춘다** — 첨부 다운로드·접속이 1회 실패하면 반복하지 않고 `partial`로 저장한 뒤 `BACKLOG.md`에 사유와 필요한 조치를 적는다.

## 작성 원칙

- 자료에 없는 말을 만들지 않는다. "환자가 ~해야 한다"는 식의 의료 조언을 쓰지 않고 **원문이 안내하는 내용**과 **적용 한계**를 쓴다.
- 보험 지급 판단은 상품명·가입시기·실제 약관·진단/치료 내역 없이는 확정하지 않는다. 공적 제도(건강보험·산정특례·지원사업)와 민영보험을 섞지 않는다.
- 개인정보·고객 서류는 이 폴더에 넣지 않는다. (실손 증권, 진단서, 영수증 등 → 기존 별도 위치 유지, 비식별 처리 후 사례 폴더)
- 큰 원문(PDF 수십 MB)은 저장소에 두지 않고 Drive 링크로 참조하며, 장·쪽 단위 요약 자료를 별도로 만든다.
- `verified`는 "원문과 요약이 일치한다"는 뜻이지 "의료적으로 옳다/당신에게 해당한다"는 뜻이 아니다. 의료인 검토 전까지 모든 자료의 `reviewer`에 미실시를 유지한다.

## 영상에 쓰기 직전 체크리스트

1. 사용하는 모든 문장·수치에 `MED-` 번호가 붙어 있는가
2. 해당 자료의 `status`가 `verified`인가 (`partial`은 확보된 범위까지만)
3. `recheck_by`가 지났거나 3개월 이상 지났으면 원문 개정 여부 재확인 → `checked` 갱신
4. `tier C` 자료를 국내 제도의 근거로 쓰고 있지 않은가
5. 자료의 `미검증·사용 금지` 섹션에 걸리는 표현이 없는가
6. 사용한 영상·장면을 `video_use`에 기록

## 기존 Drive 자료와의 관계
- Drive의 `01_질병별 공통자료/신장암` 이하 txt·PDF는 **보관본**으로 그대로 둔다(파일명 변경 없음). 각 자료의 `drive_file`에 링크가 있다.
- Drive 시트 `휴휴휴 의료정보_자료목록과 운영흐름`은 2026-10-11 기준 이전 이후 이 체계에서는 갱신하지 않으며, 이 저장소가 정본이다. 시트에 연결된 ChatGPT 시간별 자동 작업(`자동 작업 ID 6aca10d4…`)은 이 저장소와 이중으로 번호를 붙이게 되므로 중지하는 것을 권장한다.
